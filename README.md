# TRPG Messenger 0.2

초보 키퍼와 탐사자가 **카톡처럼 각자 시간 날 때 답하는 비동기 TRPG**를 하기 위한 0.2 테스트판입니다.

## 0.2에서 되는 것

- 키퍼가 방 생성 → 6자리 방 코드 공유
- 여러 탐사자가 각자 휴대폰에서 같은 방에 입장
- 서로 동시에 접속하지 않아도 기존 로그를 읽고 답장
- 캐릭터 사진 없이 이름 명찰만 사용
- 대사 / 지문 / 사담 구분
- 키퍼가 KPC / NPC 명찰을 만들고 직접 연기
- 장면 생성
- 장면에 등장할 탐사자 선택
- 미리 써둔 시작 지문 버튼 전송
- 키퍼 전용 장면 메모
- 판정값 직접 등록
- 1D100 / 2D6 / 1D20
- 목표값 기준 성공 / 실패 자동 표시
- 장면별 로그 / 전체 로그 복사
- 초보자용 용어 설명

## 용어

- **키퍼**: 이야기를 진행하는 사람.
- **탐사자**: 플레이어가 맡은 캐릭터.
- **KPC/NPC**: 키퍼가 직접 연기하는 등장인물.
- **장면**: 이야기를 작은 구간으로 나눈 것. 인세인을 몰라도 사용 가능.
- **대사**: 캐릭터가 말한 것.
- **지문**: 상황/행동 묘사.
- **사담**: 캐릭터가 아니라 플레이어끼리 하는 메타 대화.
- **판정**: 주사위를 굴려 성공/실패를 확인하는 것.

## GitHub Pages로 올리는 순서

1. 이 ZIP을 풀고 새 GitHub 저장소에 파일 4개를 업로드합니다.
2. Supabase에서 무료 프로젝트를 하나 만듭니다.
3. Supabase의 **SQL Editor**에서 `supabase_setup.sql` 내용을 실행합니다.
4. Supabase **Project Settings > API**에서 Project URL과 anon key를 확인합니다.
5. GitHub의 `config.js`를 열어 URL과 KEY 두 값을 수정하고 Commit 합니다.
6. GitHub 저장소의 **Settings > Pages**에서 배포를 켭니다.
7. 만들어진 GitHub Pages 링크를 실험자에게 보냅니다.
8. 키퍼가 방을 만든 뒤 6자리 코드를 팀원에게 보냅니다.
9. 탐사자들은 같은 링크에서 방 코드 + 캐릭터 이름으로 입장합니다.

## 초보 키퍼 테스트 추천

1. 키퍼가 방 생성.
2. 실험자 1~3명이 탐사자로 입장.
3. 키퍼가 `참가자` 탭에서 KPC 하나 추가.
4. `장면` 탭에서 첫 장면 생성.
5. 시작 지문을 보내기.
6. 탐사자가 나중에 들어와 대사/지문으로 답하기.
7. 키퍼가 KPC 명찰로 바꿔 답하기.
8. 판정 하나 등록해서 성공/실패가 모두에게 보이는지 확인.
9. 다음 장면으로 넘기기.
10. 앱을 닫았다가 다시 열어 로그가 남는지 확인.

## 주의

0.2는 **친구 몇 명과 하는 비공개 테스트용**입니다. 현재 데이터베이스 정책은 테스트 편의를 위해 익명 사용자가 읽고 쓸 수 있게 열어둔 상태입니다. 공개 서비스/유료 서비스로 배포하기 전에는 로그인과 방별 접근 권한을 넣어야 합니다.

Supabase의 Postgres Changes는 작은 테스트판에는 간단하지만, Supabase 공식 문서는 큰 규모에서는 Broadcast 방식이 더 확장성 있는 선택이라고 안내합니다. 0.2에서는 구현을 단순하게 유지하기 위해 Postgres Changes를 사용합니다.
